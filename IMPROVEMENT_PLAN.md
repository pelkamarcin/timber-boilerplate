# Plan modernizacji motywu Timber Boilerplate

> Status szczegółowy i odhaczanie wykonanych kroków znajdziesz w pliku `PROGRESS.md`. Aktualizuj oba dokumenty
> równolegle: ten opisuje pełny zakres, a `PROGRESS.md` raportuje bieżący stan.

Dokument zbiera działania potrzebne do uporządkowania architektury (PHP/Twig/JS/SCSS), maksymalnej optymalizacji
wydajności (Lighthouse / Speed Index), minimalizacji wtyczek, wdrożenia strategii ikon (SVG sprite) oraz poprawy obsługi
ACF Blocks z pełnym podglądem w edytorze. Każda sekcja zawiera konkretne kroki, zależności i przewidywany wpływ.

## 4. Strategia ikon (SVG Sprite)

1. **Źródła ikon**: umieść pliki w `resources/icons/src`. Nazewnictwo `icon-{name}.svg`.
2. **Build**: użyj np. `vite-plugin-svg-icons` lub `svg-sprite-loader` z konfiguracją generującą `dist/icons/sprite.svg`
   podczas `npm run dev/build`.
3. **PHP/Twig**: dodaj helper `Site\App\Support\Icons::render('name', attrs = [])` i Twig partial `partials/icon.twig`
   wywołujący `<svg><use href="#sprite-name"></use></svg>`.
4. **Lazy inline**: dla pojedynczych ikon w krytycznych miejscach (logo) wstawiaj inline SVG (import przez Vite `?raw`).
5. **Fallback**: przygotuj `nosvg` klasę (CSS) w razie braku wsparcia + PNG fallback (opcjonalny, generowany w buildzie
   przez `sharp`).
6. **Dokumentacja**: sekcja w `README` z instrukcją dodania nowej ikony.

Wpływ: brak konieczności korzystania z zewnętrznych wtyczek ikon, spójna obsługa w Twig, minimalna ilość requestów.

## 7. Roadmap (fazy)

1. **Faza 0 – Przygotowanie** (0.5 dnia)
    - Backup, `npm install`, `composer install`, audyt obecnych hooków.
2. **Faza 1 – Architektura** (1.5 dnia)
    - Refaktor struktury `src/`, autoload, dokumentacja konwencji.
3. **Faza 2 – Build & Performance** (2 dni)
    - Aktualizacja Vite, krytyczny CSS, lazy modules, obrazki.
4. **Faza 3 – Funkcje bez wtyczek + ikony** (1 dzień)
    - Shortcodes, cache layer, SVG sprite.
5. **Faza 4 – ACF Blocks** (1 dzień)
    - Editor assets, generator bloków, spójność Twig.
6. **Faza 5 – QA/CI** (1 dzień)
    - Testy, linty, Lighthouse CI, workflow.
7. **Faza 6 – Stabilizacja** (0.5 dnia)
    - Testy regresyjne, dokumentacja wdrożenia, przekazanie.

Szacowany łączny czas: ~7 dni roboczych (do korekty po weryfikacji zakresu). Priorytetowe są fazy 1–3, bo odblokowują
łatwe dodawanie funkcji i lepsze wyniki Lighthouse.
